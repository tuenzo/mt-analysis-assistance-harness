# Keemart 系统展示逐字演讲稿

下面是一版含记忆模块的逐字讲稿，承接前一段业务落地介绍，重点展示 Agent 分析、看板下钻、追问解释和项目级记忆沉淀。

## 逐字稿

下面接着上一部分，直接进入平台操作。当前项目是 Keemart 沙特月末促销复盘，右上角显示本项目接入的美团大模型。页面左侧还有项目管理、数据接入、报告、记忆等模块，现场重点看 Agent 分析和结果看板如何协同。

先在 Agent 分析页点击建议输入“活动是否有效”。系统自动发送问题：请评估本轮促销是否真正有效，并区分月末发薪自然高峰和促销带来的真实增量。可以看到，Agent 先说明判断思路，再依次调用数据校验、品类日面板构建和 PSM-DID 评估。这里的价值是，大模型负责理解经营问题和规划路径，后端工具负责按统一口径计算，所以结论有可追溯依据。它最终给出的判断是：活动存在可归因增量，不是单纯吃到月末自然高峰。

接着切到结果看板。上方卡片汇总总体效果和增量拆解，中间的 Pareto、瀑布图、趋势图分别对应品类集中度、增量来源和活动期走势。这里点击“GMV 净增量”卡片，右侧会展开明细抽屉，可以看到每日实际 GMV、自然基线和净增量的对应关系；如果评委关心口径，也可以继续追问 Agent：“为什么这里把曝光贡献作为主引擎？”Agent 会回到报告依据，解释曝光、折扣和发薪窗口的不同作用，把看板证据和业务判断连起来。

最后看四象限气泡图和右侧策略卡片。看板把品类落到优先加码、稳定维持、控制折扣和避免打扰四类动作；气泡显示具体品类，大小代表贡献。这样，系统不是只给分析结论，而是把模型判断继续翻译成下一轮可执行的投放策略。

最后切到记忆模块。这里展示的是本次复盘自动生成的候选记忆，包括活动效果识别口径、曝光与折扣的资源角色、下一轮品类分层策略和边际收益风险边界。候选内容不会直接进入长期上下文，需要在项目内审核后再写入。现场点击一条“通过写入”，右侧项目级记忆会同步更新。下一轮同类活动启动时，Agent 会先读取这些项目记忆，把历史经验作为分析上下文；同时，原始订单明细和临时假设不会自动沉淀，用户级同步也需要显式确认。这就是把一次性复盘转成组织资产的过程。
