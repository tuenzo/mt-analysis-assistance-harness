# Keemart Agent 对话流程设计

## 设计目标

Agent 分析部分通过“建议输入”触发自然语言问题，系统自动发送问题，并按事件流返回 Agent 规划、工具调用、产物提示和最终回答。展示时不显式说明演示属性，而是模拟运营人员真实使用系统。

新版现场演示采用“一轮 Agent 主对话 + 看板明细下钻 + 一轮 Agent 追问解释 + 记忆审核写入”的节奏，避免在同一页面堆叠太多问题，同时展示系统可以从结果回到解释，并把复盘经验沉淀为项目级记忆。

## 演示主线

1. 活动是否有效：展示大模型如何理解业务问题，并调度数据校验、品类日面板、PSM-DID 等工具，判断活动是否存在可归因增量。
2. 结果看板：集中展示总体效果、增量来源、资源响应和策略建议，并通过 `GMV 净增量` 卡片下钻查看口径细节。
3. 追问解释：从看板回到 Agent，询问“为什么把曝光贡献作为主引擎”，展示 Agent 如何把指标证据、模型结果和经营建议串起来。
4. 记忆审核：展示本次复盘生成的候选记忆，审核后写入项目级记忆，供下一轮活动复用。

## 建议输入 1：活动是否有效

用户点击发送：

```text
请评估本轮促销活动是否真正有效，注意区分月末发薪自然高峰和促销带来的真实增量。
```

系统返回顺序：

1. Agent 说明任务理解：不能直接把 GMV 上涨等同于促销效果，需要控制发薪周期和品类差异。
2. `data.validate`：返回观测区间、活动窗口、品类数和用户数。
3. `panel.build_category_day`：返回品类日面板、活动窗口和发薪窗口重叠信息。
4. `analysis.run_psm_did`：返回活动后仍存在可归因抬升，以及安慰剂检验通过。
5. Agent 最终回答：活动有效，但结论来自控制自然周期后的识别结果。

现场讲法：

- 重点讲“Agent 先规划，再调用工具”，让数字作为页面证据，不展开逐项朗读。
- 强调美团开发的大模型负责推理和调度，受控工具负责确定性分析。

## 建议输入 2：增量来自哪里

该问题保留在系统中，但本版含记忆模块讲稿不单独点击。

用户点击发送：

```text
请继续分解 GMV 增量来源，说明订单量和客单价分别贡献多少。
```

系统返回顺序：

1. Agent 说明分析计划：构造反事实基线，并按 GMV = Order × AOV 拆解。
2. `analysis.run_increment_decomposition`：返回实际 GMV、反事实 GMV、净增量和提升率。
3. artifact 提示：生成增量拆解卡片。
4. Agent 最终回答：说明增长主要来自订单量扩张，客单价贡献用于判断增长质量。

现场处理：

- 不单独点击，避免时间过长。
- 在结果看板顶部 KPI 和瀑布图处统一讲“增量来源”能力。

## 建议输入 3：资源应投给谁

该问题保留在系统中，适合更长版本演示。本版含记忆模块讲稿中不单独点击，策略结果在结果看板里展示。

用户点击发送：

```text
基于这些结果，下一轮资源应该怎么投？请区分曝光、折扣、发薪窗口和重点品类。
```

系统返回顺序：

1. Agent 说明策略生成思路：结合增量分解、GPS 剂量反应和 Uplift 排序。
2. `analysis.run_gps_uplift`：返回曝光和折扣的边际响应、长尾和非发薪期风险。
3. `strategy.generate`：返回优先加码、稳定维持、控制折扣、避免打扰四类策略。
4. artifact 提示：结果看板已更新。
5. Agent 最终回答：曝光作为主引擎，折扣作为微调器，资源集中给高响应品类和关键窗口。

现场讲法：

- 重点讲系统能把模型结果转成可执行动作。
- 不展开读代表品类，把具体品类留到结果看板的四象限气泡图中展示。

## 建议输入 4：解释曝光贡献

用于看板下钻后的追问。用户点击发送：

```text
为什么这里把曝光贡献作为主引擎？请结合看板里的净增量、LocalGap 和 Uplift 结果解释。
```

系统返回顺序：

1. Agent 说明追问理解：需要把 GMV 净增量、LocalGap 增量分解和 Uplift 四象限合在一起解释。
2. `analysis.explain_dashboard_metric`：读取顶部 KPI、瀑布图、四象限和策略卡片的证据链。
3. Agent 最终回答：曝光对应交易规模扩张，订单量贡献更高，LocalGap 显示曝光贡献更强；折扣更适合少数价格敏感品类和发薪窗口，避免大范围加深。

现场讲法：

- 这一步展示“看板有疑问，可以回到 Agent 继续问”。
- 重点讲系统能把看板证据解释成业务语言，而不是只展示静态图表。

## 不展示内容

- 不在 Agent 页面展示讲稿。
- 不展示系统说明型大段文本。
- 不读完整报告结论。
- 不逐个朗读页面数字，指标只作为证据支撑判断。

## 记忆模块展示

进入左侧 `记忆` 页面后，展示三类内容：

1. 候选记忆：活动效果识别口径、曝光与折扣的资源角色、下一轮品类分层策略、边际收益风险边界。
2. 审核动作：点击一条候选记忆的 `通过写入`，说明稳定经验需要经过项目内审核后才进入长期上下文。
3. 项目级记忆：右侧已存储内容会同步更新，下一轮同类活动启动时 Agent 可优先读取这些记忆作为上下文。

现场讲法：

- 重点讲“沉淀经验，不沉淀原始敏感数据”。
- 强调用户级记忆同步需要显式确认，项目级记忆服务于当前项目和后续同类活动。
